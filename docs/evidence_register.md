# Cynbit Technologies — Passive Technical Evidence Register

**Target Domain**: `https://cynbit.in/` (Canonical: `https://www.cynbit.in/`, Subdomain: `https://portal.cynbit.in/`)  
**Assessment Date**: November 1, 2026  
**Auditor**: Chahat Modi  
**Assessment Type**: Non-intrusive, passive technical observation  

---

## 1. Classification Definitions

- **[OBSERVED]**: Directly verified via HTTP response headers, script code, certificate exchange, or DNS responses.
- **[INFERRED]**: A sound technical conclusion derived from visible architectural characteristics.
- **[POTENTIAL RISK]**: An engineering or security risk identified from observable configurations that would require internal review to confirm exploitability.
- **[NOT VERIFIABLE]**: An internal backend capability (e.g., ORM sanitization, database indexes, server-side queue workers) that cannot be confirmed from external observation alone.

## 2. Evidence Register

| ID | Area | Observation | Evidence | Risk | Recommendation |
|---|---|---|---|---|---|
| **EVD-001** | Routing & Canonical URL | Apex domain redirects to `www` subdomain via HTTP 307 Temporary Redirect. | **[OBSERVED]** `HTTP/1.1 307 Temporary Redirect`<br>`Location: https://www.cynbit.in/` | **[POTENTIAL RISK]** A 307 Temporary Redirect does not transfer search engine link equity as effectively as a 301 Permanent Redirect, and user agents may repeat requests to the apex domain unnecessarily. | Implement a 301 Permanent Redirect rule for canonical domain consolidation at the CDN/DNS edge. |
| **EVD-002** | Hosting & CDN Infrastructure | Hosted on Vercel Global Edge Network with Mumbai (BOM1) Point of Presence. | **[OBSERVED]** `Server: Vercel`<br>`X-Vercel-Cache: HIT`<br>`X-Vercel-Id: bom1::bzzzz-1793508031357-d60affc857f8` | **[OBSERVED]** Fast regional latency for Indian visitors (BOM1). Infrastructure relies heavily on Vercel's serverless edge capabilities. | Maintain regional edge caching; ensure serverless cold starts are monitored for dynamic routes. |
| **EVD-003** | Web Framework & Rendering | Next.js App Router with Server-Side Rendering (SSR) & Static Site Generation (SSG). | **[OBSERVED]** `X-Nextjs-Prerender: 1`<br>`Vary: rsc, next-router-state-tree, next-router-prefetch`<br>`X-Powered-By: Next.js` | **[INFERRED]** Next.js App Router with React Server Components (RSC) is the primary full-stack web framework. | Disable framework version/fingerprinting banners (`poweredByHeader: false` in `next.config.js`). |
| **EVD-004** | Cross-Origin Resource Sharing (CORS) | Wildcard CORS header (`Access-Control-Allow-Origin: *`) returned on root HTML documents and error pages. | **[OBSERVED]** `Access-Control-Allow-Origin: *` returned on `https://www.cynbit.in/` and `https://portal.cynbit.in/`. | **[POTENTIAL RISK]** Emitting wildcard CORS headers on HTML responses is unnecessary and can allow malicious third-party scripts on other origins to read document content if authenticated sessions or sensitive tokens are rendered. | Restrict `Access-Control-Allow-Origin` strictly to verified API endpoints and trusted frontend origins; do not emit CORS on HTML documents. |
| **EVD-005** | Transport Layer Security (TLS) | Strong TLS 1.3 encryption with AES-128-GCM cipher suite and Let's Encrypt certificate. | **[OBSERVED]** Protocol: `TLS 1.3`<br>Cipher: `Aes128`<br>Issuer: `CN=YR2, O=Let's Encrypt, C=US`<br>Validity: `25-09-2026` to `24-12-2026`<br>`Strict-Transport-Security: max-age=63072000` | **[OBSERVED]** Modern cryptography in transit. HSTS preloads for 2 years (63072000 seconds). | Maintain automated certificate renewal via Vercel / Let's Encrypt and verify HSTS `includeSubDomains; preload`. |
| **EVD-006** | Content Security Policy (CSP) | No `Content-Security-Policy` header is present on any responses. | **[OBSERVED]** Headers inspected: No `Content-Security-Policy` or `Content-Security-Policy-Report-Only` returned. | **[POTENTIAL RISK]** In the event of a Cross-Site Scripting (XSS) injection in client-side code, the browser has no restrictions on executing unauthorized inline scripts or exfiltrating data to external domains. | Implement a strict CSP defining allowed `default-src 'self'`, script nonces or hashes, `style-src`, and `connect-src` directives. |
| **EVD-007** | Clickjacking Defense | No `X-Frame-Options` or CSP `frame-ancestors` directive present. | **[OBSERVED]** Neither `X-Frame-Options: DENY/SAMEORIGIN` nor `Content-Security-Policy: frame-ancestors` returned. | **[POTENTIAL RISK]** The site can be embedded within an `<iframe>` on an external malicious website, exposing users to UI clickjacking attacks. | Set `X-Frame-Options: DENY` (or `SAMEORIGIN`) and configure `frame-ancestors 'none'` in CSP headers. |
| **EVD-008** | MIME Sniffing Protection | Missing `X-Content-Type-Options: nosniff`. | **[OBSERVED]** `X-Content-Type-Options` header absent from response. | **[POTENTIAL RISK]** Legacy browsers may attempt to execute files based on content rather than declared MIME type, leading to MIME-confusion attacks. | Enforce `X-Content-Type-Options: nosniff` globally across all responses. |
| **EVD-009** | Information Disclosure via Headers | Server framework and route matching disclosed in HTTP response headers. | **[OBSERVED]** `X-Powered-By: Next.js`<br>`Server: Vercel`<br>`X-Matched-Path: /`<br>`X-Next-Error-Status: 404` | **[POTENTIAL RISK]** Technology fingerprinting aids attackers in mapping framework vulnerabilities and tailoring exploits. | Suppress `X-Powered-By` header in Next.js configuration and strip unnecessary internal routing metadata headers in production. |
| **EVD-010** | Robots.txt Route Disclosure | `robots.txt` explicitly disallows `/api/`, `/admin/`, and `/portal/`. | **[OBSERVED]** `Disallow: /api/`<br>`Disallow: /admin/`<br>`Disallow: /portal/` | **[INFERRED]** Disclosing sensitive path names in `robots.txt` acts as an information beacon for attackers seeking administrative or internal interfaces. | Do not rely on `robots.txt` for obscurity; protect sensitive administrative interfaces using strict network filtering, VPNs, or WAF access policies. |
| **EVD-011** | Administrative Portal Isolation | Dedicated portal subdomain `portal.cynbit.in` (and 307 redirect from `/portal`). | **[OBSERVED]** `cynbit.in/portal` redirects to `https://portal.cynbit.in/`. `portal.cynbit.in` returns HTTP 200 with portal login screen. | **[OBSERVED]** Clear logical separation between public marketing content and internal administrative functions. | Maintain domain-level isolation and ensure cross-subdomain cookie leakage is prevented. |
| **EVD-012** | Authentication Mechanism | Portal authentication relies on a single "Security Key" (password-only) without username or multi-factor authentication. | **[OBSERVED]** JS Chunk `app/portal/page-ba479285e84c64b5.js`: Form contains only `<input type="password" ... placeholder="••••••••">`. Submits `password` to server action `loginToPortal`. | **[POTENTIAL RISK]** Shared administrative credential prevents non-repudiation, individual user audit logging, individual credential revocation, and lacks Multi-Factor Authentication (MFA). | Transition to individual user identities (e.g. Email + Password + MFA / WebAuthn) with Role-Based Access Control (RBAC). |
| **EVD-013** | Session Storage & State | Portal stores last activity timestamp in browser `localStorage`. | **[OBSERVED]** Code in `page-ba479285e84c64b5.js`:<br>`localStorage.setItem("cynbit_portal_last_activity", Date.now().toString());` | **[POTENTIAL RISK]** Data in `localStorage` is accessible to any script executing in the document context. If an XSS vulnerability occurs, session indicators can be inspected or tampered with. | Store sensitive session identifiers exclusively in `HttpOnly`, `Secure`, `SameSite=Strict` cookies or manage stateless signed JWTs with short expiries. |
| **EVD-014** | Admin Route Guards | Accessing `/dashboard` on `portal.cynbit.in` unauthenticated triggers HTTP 307 redirect to `/`. | **[OBSERVED]** `GET https://portal.cynbit.in/dashboard` -> `HTTP/1.1 307 Temporary Redirect` -> `Location: /` | **[OBSERVED]** Server-side authentication guard is enforced prior to rendering protected dashboard content. | Maintain server-side route guards and verify that all dashboard API calls validate authentication independently of UI redirects. |
| **EVD-015** | Inquiry Data Submission | Contact inquiries handled via Next.js Server Action (`submitInquiry`) with client-side HTML5 validation. | **[OBSERVED]** JS Chunk `app/(marketing)/contact/page-a581c8d7462124d9.js` creates reference `submitInquiry` (ID: `40247ba4465344b3386595bab4303317cdcce907df`). Fields: `fullName`, `email`, `company`, `industry`, `message`. | **[POTENTIAL RISK]** If server action lacks rigorous Pydantic/Zod-style server-side schema validation, empty strings, payload truncation, or oversized payloads could cause backend processing errors. | Implement strict backend schema validation (length limits, regex sanitization, whitespace trimming) independent of client forms. |
| **EVD-016** | Career Application Submission | Career submissions use Server Action (`submitCandidateApplication`) with complex serialized JSON payloads. | **[OBSERVED]** JS Chunk `app/(marketing)/careers/[slug]/page-082725dddd6cb4ac.js` appends `JSON.stringify(educationData)` into FormData. Handles `isDuplicate` and `trackingUrl`. | **[INFERRED]** Backend checks for duplicate applicants and provides candidate tracking. Processing client-serialized JSON in FormData requires careful deserialization safety. | Ensure robust schema parsing on deserialized JSON; validate maximum array lengths and field limits to prevent resource exhaustion. |
| **EVD-017** | DNS & Email Authentication | SPF record points to `secureserver.net` while MX points to Microsoft Outlook (`cynbit-in.mail.protection.outlook.com`). DMARC policy is set to `p=none`. | **[OBSERVED]** MX: `cynbit-in.mail.protection.outlook.com`<br>SPF: `v=spf1 include:secureserver.net -all`<br>DMARC: `v=DMARC1; p=none;` | **[POTENTIAL RISK]** Inconsistent SPF alignment (Outlook MX not included in SPF) may cause legitimate emails to fail SPF. DMARC `p=none` does not enforce quarantine or rejection of spoofed emails. | Update SPF to include `include:spf.protection.outlook.com` and upgrade DMARC policy from `p=none` to `p=quarantine` or `p=reject`. |
| **EVD-018** | Database & Server Internals | Underlying database engine, query mechanisms, and transaction isolation levels. | **[NOT VERIFIABLE]** No internal database errors, connection strings, or query traces are exposed externally. | **[NOT VERIFIABLE]** Cannot determine whether PostgreSQL, MySQL, Supabase, or MongoDB is utilized without internal architecture access. | For the reference implementation, employ MySQL 8.0+ with SQLAlchemy 2.x ORM, Alembic migrations, parameterized queries, and strict transaction rollback. |
